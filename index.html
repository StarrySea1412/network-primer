01第一章

DNS：互联网的电话簿

浏览器不认识 example.com，只认识 93.184.216.34。把名字变成数字的，是递归解析器和它身后的一整条问路链。

第一次查询要走完全程：你的电脑问递归解析器，解析器不会答就去问根服务器（「.com 归谁管？」），根说去问 .com TLD，TLD 说去问 权威服务器，权威才给出最终答案——答案沿原路返回，每层顺手记在本子上（缓存）。TTL 一到，本子上的记录过期，一切重来。

// 点「查询」开始。第一次走全程，第二次看缓存。
确定性模拟：各跳延迟按真实量级预设（根 ~15ms / TLD ~20ms / 权威 ~25ms）。「清空缓存」后重查会走全程——这就是为什么第一次打开网站总是最慢的。
为什么要有缓存：全球每天几千亿次查询，如果每次都打到根服务器，根会把全世界拖垮。TTL（生存时间）就是每条记录的保质期——网站换 IP 时，最长要等旧 TTL 过期，全世界的缓存才肯忘掉旧地址。
02第二章

TCP：先握手，再说话

拿到 IP 之后，还不能直接要数据——要先和服务器握三次手，同步两边的「计数器」。计数器对上了，连接才算建立。

三次握手：客户端发 SYN (seq=x)「我想说话，我的计数从 x 开始」；服务器回 SYN+ACK (seq=y, ack=x+1)「收到 x，我这边从 y 开始」；客户端再回 ACK (ack=y+1)「收到 y」。一来一回一回，双方都确认了「我能说、你能听、我能听」。

// 点「下一步」逐步走完三次握手和四段数据。
seq/ack 按真实语义递增（SYN 消耗一个序号）。注入丢包后：发送方等不到 ack，超时重传同一个报文；接收方收到重复报文会丢弃但仍重发 ack——这就是 TCP 可靠性的全部魔法。
为什么是三次不是两次：两次握手无法让服务器确认「客户端能收到自己说的话」。第三次 ACK 就是客户端在说「你刚才那句话我听到了」——缺少它，服务器的资源会被浪费在永远等不到回应的半连接上（经典 SYN Flood 攻击正是利用这一点）。
03第三章

封装：洋葱式的四层信封

你的「你好」发出去之前被套了四层信封：HTTP 套进 TCP、TCP 套进 IP、IP 套进以太网帧——每层只管拆自己那层。

分层的意义是各管一段：应用层管「说什么」，传输层管「可靠送达」，网络层管「走哪条路」，链路层管「这一跳怎么过」。收信方按相反顺序拆信封，每拆一层，就多知道一件事该交给谁。

04第四章

HTTP：一场你来我往的对话

连接建好，浏览器发请求，服务器给应答。请求行、状态行、头部、正文——每个字段都在说话。

选一个状态码，看服务器怎么答、浏览器接着做什么。301 和 404 的区别不只是数字：301 会触发浏览器再发一次请求（去新地址），404 只是展示错误页——重定向是有成本的，每 301 一次就是一次额外的完整往返。

05第五章

路由：每一跳都在减一

从你家路由器到太平洋对岸的服务器，一个包要经过十几台路由器。每台路由器做同一件事：看一眼目标 IP，查表选下一跳，TTL 减一。

TTL（生存时间）是 IP 头里的一个小计数器，发包时设为 64，每过一台路由器减一，减到 0 就地丢弃——没有它，一个配置错误的包会在网络里永远打转。traceroute 正是利用这个机制：故意发 TTL=1、2、3… 的包，逼每台路由器「自报家门」。

06第六章

速查卡：按下回车后的六件事

如果只带走六句——

① 名字要先变数字

DNS 走完要几十到几百 ms——第一次访问网站慢，一大半慢在这里。

② 握手两次才开谈

TCP 三次握手 + HTTPS 的 TLS 握手——新连接有固定门槛，所以连接要复用。

③ 四层信封各管一段

应用说什么、传输保到达、网络选路径、链路过一跳。排障就是问「哪层出的错」。

④ 状态码是行动指令

200 收货、301 再来一次、304 用缓存、404 认错、500 服务器自己扛——每个码都有后续动作。

⑤ TTL 防永生包

每跳减一、归零即弃。traceroute 用它逼路由器自报家门。

⑥ 延迟大头是物理

光速 × 光纤折射率 ≈ 200km/ms——跨洋 100ms+ 是物理定律，代码优化省不出来。

按下回车，四百毫秒，一场横跨半个地球的接力。——网络手册 · 完
